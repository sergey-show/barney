# Плагины

**Русский** · [English](plugins.md)

Плагин — это способность в **теле**, не в ядре. Barney может прочитать его, открыть UI или вырастить новый после сработавшего recovery.

Для новой способности предпочитайте плагин/навык, а не новый MCP. [MCP](mcp.ru.md) — только если нужен внешний stdio-процесс.

## Где живут

```
~/.barney/plugins/<name>/
  plugin.json      # имя, версия, описание, опционально ui
  SKILL.md         # или PLUGIN.md — что делать
  ui.html          # опциональный UI портала
  mcp.json         # опциональный рецепт MCP
```

Также сканируются legacy-оверлеи (при совпадении имени побеждает Barney-плагин):

- `~/.barney/skills/`
- `~/.barney/mcp/`
- AgentSkills из Claude / OpenCode / Codex / Claw, если эти папки есть на машине

Список **Settings → Plugins** в Web — это каталог. Отдельной формы «поставить плагин» нет: файлы кладут в тело или просят Barney их написать.

## Манифест

`plugin.json`:

```json
{
  "name": "file-viewer",
  "version": "1",
  "description": "Показать файл worktree в портале",
  "ui": "ui.html"
}
```

Имя — kebab-case (`file-viewer`). В `SKILL.md` можно AgentSkills-frontmatter (`name`, `description`); `{baseDir}` в теле заменяется на каталог плагина.

Навык, выросший из recovery, пишется как `learned-<класс-провала>` и стартует в **карантине**. Пока его не повысят, Barney не показывает его в каталоге и не запускает.

## Оператор

1. Создайте `~/.barney/plugins/<name>/`.
2. Добавьте `plugin.json` и `SKILL.md` (и `ui.html`, если нужна панель в портале).
3. Перезапуск не обязателен: следующий `plugin_list` / обновление Settings увидит папку.
4. Git тела в `~/.barney` фиксирует изменение (`self_commit` / idle `become:`).

## Агент

На полном ходе Barney может:

| Tool | Что делает |
|---|---|
| `plugin_list` | Каталог в `~/.barney` и оверлеях |
| `plugin_read` | Тело навыка или файл внутри плагина |
| `plugin_write` | Создать/обновить файл в `~/.barney/plugins/<name>/` |
| `plugin_open` | Открыть `ui.html` в портале (или markdown, если UI нет) |

Типичный рост:

1. `plugin_list` — не плодить дубликат.
2. `plugin_read` — следовать уже существующей схеме.
3. Если ничего не подходит и recovery реально сработал — маленький навык, не новый MCP.
4. `plugin_open`, когда оператору нужна панель.

`plugin_write` пишет в тело. `src/` он не патчит. Самописные плагины принимаются в карантин, пока не докажут себя.
